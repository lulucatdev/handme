# Handme v0.1 — 设计文档

## 概述

Handme 是一个 macOS 文件收件箱应用。用户通过 CLI 命令 `handme <文件>` 将文件放入收件箱，在主窗口中查看和操作。

**技术栈：** 纯 Swift + SwiftUI，macOS 14+，非沙盒，直接分发。

**首期范围：** CLI + 主窗口应用。菜单栏托盘面板、全局快捷键等留后续迭代。

## IPC 方案：共享 SQLite + FSEvents

CLI 和 App 共享一个 SQLite 数据库。CLI 直接写入，App 通过 DispatchSource 文件监听自动刷新。

选择理由：
- Handme 的 IPC 需求是单向的（CLI → 收件箱）
- CLI 不依赖 App 是否运行
- 数据天然持久化，crash-safe
- SQLite WAL 模式处理并发读写

**SQLite 库：** 使用 GRDB.swift（成熟的 Swift SQLite 封装，支持 WAL、migrations、线程安全）。

**并发安全：** CLI 和 App 均设置 `PRAGMA busy_timeout = 3000`，处理瞬时锁竞争。

**文件监听：** App 监听数据库所在目录（`~/Library/Application Support/Handme/`）而非单个 db 文件，因为 WAL 模式下写入先到 `-wal` 文件，仅监听 `inbox.db` 可能漏掉写入。

## 数据模型与持久化

### 数据库

位置：`~/Library/Application Support/Handme/inbox.db`

```sql
CREATE TABLE inbox_items (
    id          TEXT PRIMARY KEY,   -- UUID
    file_path   TEXT NOT NULL,      -- 文件绝对路径
    file_name   TEXT NOT NULL,      -- 文件名（冗余存储，排序/过滤用）
    added_at    REAL NOT NULL,      -- Unix timestamp
    file_exists INTEGER DEFAULT 1   -- 缓存的存在状态，App 定期校验
);

CREATE UNIQUE INDEX idx_file_path ON inbox_items(file_path);
```

`file_path` 唯一索引：重复添加同一文件时 UPSERT 更新 `added_at` 并置顶。

### InboxItem

```swift
struct InboxItem: Identifiable, Hashable {
    let id: String
    let filePath: String
    let fileName: String
    var addedAt: Date
    var fileExists: Bool
}
```

### InboxStore

```swift
class InboxStore: ObservableObject {
    @Published var items: [InboxItem] = []

    func add(paths: [String]) throws        // UPSERT，重复路径更新时间
    func remove(ids: Set<String>) throws
    func removeAll() throws
    func loadAll() throws -> [InboxItem]    // 按 added_at 降序

    func startWatching()    // DispatchSource 监听 inbox.db 变化（仅 App）
    func stopWatching()

    func validateFileExistence()  // 校验文件是否仍存在
}
```

- SQLite 使用 WAL 模式，GRDB.swift 作为数据库层。
- App 启动时 `loadAll()` + `startWatching()`，db 目录变化自动触发 reload。
- `validateFileExistence()` 在 App 启动时 + 每 60 秒定时执行，在后台队列运行。文件可双向转换状态（存在 ↔ 不存在），例如外置硬盘重新挂载后文件重新标记为存在。
- CLI `--list` 也执行实时存在性检查。

### 容量与淘汰策略

- 默认上限 100 个，存为 UserDefaults，可在 Settings 中调整。
- **淘汰由 CLI `add()` 触发**：写入新 item 后，如果总数超过上限，删除 `added_at` 最早的条目。
- 不存在的文件（`file_exists = 0`）优先淘汰。
- UPSERT 会更新 `added_at`，所以刚重新添加的文件不会被淘汰。

## CLI

### 用法

```bash
handme report.pdf                    # 添加单个文件
handme *.png                         # 添加多个文件
handme ~/Downloads/archive.zip       # 绝对路径
handme .                             # 添加当前目录
handme -l / --list                   # 列出收件箱
handme -c / --clear                  # 清空收件箱（带确认）
```

### 实现

使用 Swift ArgumentParser，通过子命令区分操作模式：

```swift
@main
struct HandmeCLI: ParsableCommand {
    static let configuration = CommandConfiguration(
        commandName: "handme",
        abstract: "把文件递给自己",
        defaultSubcommand: Add.self,
        subcommands: [Add.self, List.self, Clear.self]
    )

    struct Add: ParsableCommand {
        static let configuration = CommandConfiguration(
            commandName: "add",
            abstract: "添加文件到收件箱（默认命令，可省略 add）"
        )
        @Argument(help: "要添加的文件或目录路径")
        var paths: [String]
    }

    struct List: ParsableCommand {
        static let configuration = CommandConfiguration(
            commandName: "list",
            abstract: "列出收件箱内容"
        )
    }

    struct Clear: ParsableCommand {
        static let configuration = CommandConfiguration(
            commandName: "clear",
            abstract: "清空收件箱"
        )
    }
}
```

`Add` 是 `defaultSubcommand`，所以 `handme report.pdf` 等价于 `handme add report.pdf`。`handme` 无参数时打印帮助信息。各子命令互斥，不会产生歧义。

### 输出

```
$ handme report.pdf screenshot.png
✓ report.pdf
✓ screenshot.png

$ handme report.pdf
✓ report.pdf (updated)

$ handme nonexistent.txt
✗ nonexistent.txt: no such file

$ handme -l
  report.pdf         ~/Documents/report.pdf          2m ago
  screenshot.png     ~/Desktop/screenshot.png        5m ago
```

### 路径处理

- 写入前解析为绝对路径（`URL.resolvingSymlinksInPath()`）
- 文件不存在时报错跳过
- 目录作为整体 item 添加，不递归展开

## 主窗口应用

### App 生命周期

```swift
@main
struct HandmeApp: App {
    @NSApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

    var body: some Scene {
        Window("Handme", id: "main") {
            ContentView()
        }
        Settings {
            SettingsView()
        }

```

### AppDelegate 职责

- 管理 `NSStatusItem`（菜单栏图标）
- 关闭主窗口时 App 不退出，退到菜单栏
- Dock 图标显示控制
- 全局快捷键注册（后续迭代）

### 窗口行为

- 启动时打开主窗口
- 关闭主窗口 → App 继续运行（菜单栏图标保留）
- 点击菜单栏图标 → 打开/聚焦主窗口（首期行为）
- 点击 Dock 图标 → 重新打开主窗口
- Cmd+Q → 真正退出

### 菜单栏图标

- 使用已有的 `tray-icon.png` / `tray-icon@2x.png` 作为 template image
- 首期点击 → 打开/聚焦主窗口
- **新文件指示器**：当主窗口不可见时，如果有新文件通过 CLI 加入，菜单栏图标旁显示小圆点（badge）。用户打开主窗口后圆点消失。实现方式：`NSStatusItem.button?.image` 切换为带圆点的变体图标。

### 窗口尺寸

- 默认约 480×600，可调整
- 最小 320×400

## CLI 安装

### 机制

- App bundle 内自带 `handme` 二进制（`Handme.app/Contents/Resources/handme`）
- 安装 = 创建 symlink 到用户 PATH 中的目录
- symlink 指向 bundle 内二进制，App 更新后 CLI 自动跟随

### 安装路径决策流程

1. 尝试 `/usr/local/bin/handme`（大多数用户有写权限）
2. 如果权限不足，**不请求 sudo**，自动回退到 `~/.local/bin/handme`
3. 如果 `~/.local/bin` 不在用户 `$PATH` 中，显示提示："请将 `~/.local/bin` 添加到你的 PATH"，并附上 shell 配置命令
4. 安装完成后显示实际安装路径，如 `✓ 已安装到 /usr/local/bin/handme`

### 首次启动

- 检测 `handme` 是否可用
- 空状态中展示安装引导按钮
- 点击 → 创建 symlink → 显示确认及安装路径

### Settings

- 显示当前 CLI 安装路径
- 提供"卸载命令行工具"按钮（删除 symlink）
